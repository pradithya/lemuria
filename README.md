# Lemuria

Argo CD Pull Request Automation — inspired by [Atlantis](https://www.runatlantis.io/) for Terraform.

Lemuria enables teams to preview, approve, and sync Argo CD applications through GitHub PR or GitLab MR comments. It acts as a bridge between your VCS provider and Argo CD, providing a GitOps-native workflow where infrastructure changes are reviewed as manifest diffs before deployment.

## Features

- **Multi-VCS Support** — Works with both GitHub (via GitHub App) and GitLab (via personal/group access tokens)
- **PR/MR Comment Interface** — Interact via `lemuria plan`, `lemuria sync`, `lemuria unlock`, `lemuria rollback`
- **Auto-diff** — Automatically generate and post manifest diffs when relevant files change
- **Application Locking** — Redis-based distributed locks prevent concurrent syncs to the same application
- **ApplicationSet Support** — Detect and diff applications generated by ApplicationSets (via `ownerReferences`)
- **Multi-source Support** — Handle applications with multiple repository sources
- **Approval Requirements** — Optionally require PR approval before sync (per-app or global)
- **Auto-merge** — Optionally merge PRs after successful sync
- **Rollback** — Revert to a previous deployment with `lemuria rollback --id <history-id>`
- **Web UI** — View locks, application status, and manage users
- **Multiple Auth Methods** — GitHub OAuth, GitLab OAuth, OIDC, and basic auth with RBAC


## Quick Start

### Prerequisites

- Go 1.25+
- Node.js 20+ (for frontend)
- Redis
- Argo CD instance
- GitHub App credentials and/or GitLab access token

### Installation

#### From Source

```bash
git clone https://github.com/pradithya/lemuria.git
cd lemuria
make build            # Builds frontend + backend → bin/lemuria

# Configure
cp config/lemuria.yaml.example lemuria.yaml
# Edit lemuria.yaml with your settings

# Run
./bin/lemuria -config lemuria.yaml
```

#### Docker

```bash
docker build -t lemuria:latest .
docker run -p 4141:4141 -v $(pwd)/lemuria.yaml:/app/config/lemuria.yaml lemuria:latest
```

#### Helm (Kubernetes)

```bash
helm upgrade --install lemuria oci://ghcr.io/pradithya/charts/lemuria \
  --namespace lemuria \
  --create-namespace \
  -f values.yaml
```

The Helm chart includes an optional Redis dependency (Bitnami). See `charts/lemuria/values.yaml` for all options.

## Development

### Prerequisites

```bash
make tools            # Install golangci-lint, goimports, helm-unittest
```

### Running Locally

```bash
make run              # Start Redis + backend + frontend dev server
                      # Backend: http://localhost:4141
                      # Frontend: http://localhost:5173
```

Or individually:

```bash
make run-redis        # Start Redis in Docker
make run-backend      # Build and run Go backend (uses config/test.yaml)
make run-frontend     # Start Vite dev server
```

### Building

```bash
make build            # Build frontend + backend → bin/lemuria
make build-go         # Build backend only (skip frontend, faster for dev)
make docker-build     # Build Docker image
```

### Testing

```bash
make test             # Run unit tests with race detection + coverage
```

Unit tests use a table-driven approach and cover command parsing, webhook validation/parsing, config loading, path matching, diff formatting, and model behavior. Run specific package tests with:

```bash
go test -v ./internal/commands/...   # Command parser, executor helpers, sync requirements
go test -v ./internal/webhook/...    # HMAC validation, event parsing
go test -v ./internal/config/...     # Config defaults, repo config, repo allowlisting
go test -v ./pkg/diff/...            # Diff rendering, output formatting
```

#### E2E Tests (requires k3d + Argo CD)

```bash
make e2e-setup        # Create k3d cluster with Argo CD + Redis
make test-e2e         # Run e2e tests (10m timeout)
make e2e-teardown     # Cleanup cluster
```

## API Endpoints

### Public Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/webhook/github` | POST | GitHub webhook receiver (HMAC-validated) |
| `/webhook/gitlab` | POST | GitLab webhook receiver (token-validated) |
| `/health` | GET | Health check (always returns 200) |
| `/healthz` | GET | Health check (alias) |
| `/ready` | GET | Readiness check (verifies Redis connectivity) |

### Auth Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/auth/providers` | GET | List available auth providers |
| `/auth/github/login` | GET | Initiate GitHub OAuth flow |
| `/auth/github/callback` | GET | GitHub OAuth callback |
| `/auth/gitlab/login` | GET | Initiate GitLab OAuth flow |
| `/auth/gitlab/callback` | GET | GitLab OAuth callback |
| `/auth/oidc/login` | GET | Initiate OIDC flow |
| `/auth/oidc/callback` | GET | OIDC callback |
| `/auth/basic/login` | POST | Basic auth login |
| `/auth/logout` | POST | Logout (requires auth) |
| `/auth/me` | GET | Current user info (requires auth) |

### API Endpoints (require auth if enabled)

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/status` | GET | Server status |
| `/api/v1/locks` | GET | List all locks |
| `/api/v1/locks/{app}` | DELETE | Force unlock app (admin only) |
| `/api/v1/users` | GET | List users (admin only) |
| `/api/v1/users/{id}/role` | PUT | Update user role (admin only) |
